# CS-Notes 个人在线阅读站需求文档

版本：v1.1（已确定 React 技术方案）  
日期：2026-10-12（Asia/Taipei）  
建议项目名：`cs-notes-reader`  
文档用途：作为开发、内容导入、测试和阿里云部署的实施依据。

本次交付为需求文档。下文中的功能、路径和验收指标均为建设要求，不表示网站已经开发、服务器已经检查或部署已经完成。

## 1. 已确定的产品定位

构建一个以 [CyC2018/CS-Notes](https://github.com/CyC2018/CS-Notes) 为内容来源的中文技术笔记阅读站，方便用户在电脑和手机上在线阅读、检索和接续学习。

| 决策 | 首版要求 |
| --- | --- |
| 使用对象 | 个人使用 |
| 登录方式 | 无需注册、登录 |
| 内容 | CS-Notes 的核心技术笔记 |
| 个人数据 | 进度、书签、阅读设置保存在当前浏览器 |
| 数据迁移 | 使用 JSON 文件手动导出、导入 |
| 运行方式 | 预生成静态网页，由 Nginx 提供访问 |
| 默认部署环境 | 用户的阿里云学习服务器，通过 `ssh aliyun` 连接 |
| 内容更新 | 开发者执行同步、校验、构建、发布流程 |
| 首版访问范围 | 无访问认证；承载公开笔记，个人记录不上传服务器 |

“个人使用”指功能定位。普通静态部署后，知道网址的人也可访问公开笔记；其他访问者看不到当前浏览器中的书签和进度。

## 2. 目标与首版边界

首版必须完成以下阅读闭环：

1. 从首页选择知识分类，找到章节。
2. 用中文关键词或技术名词搜索到具体内容。
3. 正确阅读文字、代码、表格、插图和参考链接。
4. 收藏章节或小节，并自动保存阅读位置。
5. 再次访问时继续阅读，必要时导出个人记录。
6. 在阿里云上获得可从用户电脑、手机访问的网页地址。

P0 为首版必须完成的能力；P1 为后续增强，不阻塞首版发布。首版不建设账号系统、云端进度同步、在线内容编辑、评论、AI 问答、付费功能或后端数据库。完整离线阅读与安装式 PWA 属于 P1。

## 3. 内容范围与组织

以原仓库 README 的分类及各目录文件的章节顺序为主要依据，建立九个知识分类。

| 分类 | 主要内容 |
| --- | --- |
| 算法 | 算法基础、剑指 Offer、LeetCode 题型 |
| 操作系统 | 概述、进程、内存、死锁、设备、链接、Linux |
| 网络 | 分层网络知识、HTTP、Socket |
| 数据库 | 数据库原理、SQL 语法与练习、MySQL、Redis |
| Java | 基础、容器、并发、JVM、I/O |
| 系统设计 | 基础、分布式、集群、缓存、消息队列、攻击技术 |
| 面向对象 | 面向对象思想、设计模式 |
| 工具 | Git、Docker、构建工具、正则表达式 |
| 编码实践 | 代码可读性、代码风格规范 |

关于页面承载作者署名、内容来源、许可、导入版本和站点说明。招聘、内推、公众号推广、Stars 徽章及历史站点迁移页不进入学习目录。

内容快照依据：已检查的 `master` 提交为 `b70121d377cb6005eb65f12b098cd5decd905669`。该快照的 `notes/` 包含 175 个 Markdown 文件，其中存在目录页、重复目录及仅用于跳转的入口。首版应根据内容清单确定有效章节数量，不把文件数量直接当作文章数量。

原笔记包含较早技术版本的内容。首版保持原文，并保留参考资料；技术纠错和现代版本补充作为独立扩展，不能在导入过程中悄悄改写原作者观点。

## 4. 页面与导航

| 页面 | 必须呈现的内容 |
| --- | --- |
| 首页 | 搜索入口、九个分类、最近阅读、继续阅读；首次访问显示明确的开始阅读入口 |
| 分类页 | 分组章节、章节顺序、已读状态；算法分类保留题型分组和题目编号 |
| 阅读页 | 面包屑、章节标题、正文、站点章节目录、当前文章目录、书签、已读按钮、上一章/下一章、原文链接 |
| 搜索面板 | 输入框、结果标题、所属分类、命中小节、摘要、空结果及加载状态 |
| 我的阅读 | 书签、最近阅读、已读章节；支持跳转和移除书签 |
| 设置/关于 | 主题、字号、数据导入导出、清除记录、来源与许可、内容版本说明 |
| 404 页 | 找不到页面说明、首页入口、搜索入口 |

桌面阅读采用左侧章节目录、中间正文、右侧文章目录。中等屏幕收起右侧目录；手机采用单列正文，章节目录和文章目录通过按钮展开。

内部路由使用稳定标识，建议形如 `/read/java/concurrency.html`。展示名称可以是中文，路由不依赖中文文件名、标题文本或章节排序。部署前缀通过配置统一注入，例如 `/cs-notes/`；页面、图片、搜索结果和个人记录跳转不得硬编码域名或根路径。

## 5. 功能需求

### F01 — 分类与章节导航（P0）

- 展示九个分类及有序章节树，当前章节高亮。
- 分类与章节顺序来自显式内容清单，数字编号按题目顺序排列，避免把第 10 题排到第 2 题前。
- 阅读页提供同组上一章和下一章，边界处隐藏不存在的方向。
- 保留有实质说明或参考资料的目录内容；纯跳转入口转换为导航或别名。
- 验收：任一有效章节均可从目录访问；导航、搜索和上一章/下一章使用同一份清单。

### F02 — 正文渲染（P0）

- 支持 Markdown 标题、列表、引用、链接、表格、代码块，以及原文常见的 `<div>`、`<img>` 排版。
- 每页有清晰的章节标题，处理缺少总标题或多个一级标题的源文件，保留原文层级关系。
- 移除 `GFM-TOC` 标记范围内的自动生成目录，由阅读站生成文章目录；保留该范围之外的实际正文。
- 代码支持语言高亮、水平滚动和复制；复制结果与代码原文一致。
- 图片保持比例，可点击放大；公式图片按图片处理，代码与公式不得丢失或被当作模板执行。
- 小屏幕下仅代码块、宽表格等内容区域允许水平滚动，整页不能横向溢出。
- HTTP/IP 学习访问环境若无法使用剪贴板 API，提供选中代码的降级操作，不显示虚假的复制成功。
- 验收：Java 并发、JVM、MySQL、HTTP、动态规划、设计模式等代表性页面文字、图表和代码均能正确阅读。

### F03 — 中文全文搜索（P0）

- 搜索范围包含章节标题、小节标题、正文和代码中的技术标识符。
- 中文查询不要求手工插入空格，英文技术词忽略大小写；展示命中摘要和所属分类。
- 标题完全匹配优先；同一章节可以返回不同小节，但不能因重复导入产生重复页面。
- 点击结果跳转到对应页面和小节；明确处理首次加载、无结果及索引加载失败。
- 支持 `Ctrl/Cmd + K` 打开，方向键选择，Enter 跳转，Esc 关闭；手机有可点击入口。
- 搜索在浏览器内执行，不向外部搜索服务发送查询词。
- 验收：索引准备完成后，以下各查询的预期内容出现在前五条结果中。

| 查询 | 预期内容 |
| --- | --- |
| 虚拟内存 | 操作系统内存管理 |
| 分布式锁 | 分布式章节相关小节 |
| Java 并发 | Java 并发章节 |
| ThreadLocal | Java 并发相关小节 |
| B+ Tree | MySQL 索引相关内容 |
| 动态规划 | LeetCode 动态规划章节 |

### F04 — 文章目录与链接定位（P0）

- 自动生成二至四级标题目录，随阅读位置高亮当前小节。
- 标题具有可复制的稳定链接；相同标题生成不同锚点。
- 跳转后标题不被固定导航遮挡，正文不会因插图加载发生明显位置跳变。
- 浏览器前进、后退及直接打开带锚点链接正常工作。
- 原仓库 `.md` 相对链接和指向该仓库笔记的 GitHub 链接转换为站内链接；其他参考资料保持外链。
- 验收：中文标题、空格文件名、重复标题、URL 编码及含双空格的源文件名都能正确定位。

### F05 — 阅读进度与继续阅读（P0）

- 自动保存每篇章节的最近阅读时间、当前小节和位置；首页提供继续阅读。
- 保存适当节流，在切换章节、关闭页面等关键时机尽量写入最新位置。
- 恢复顺序：URL 明确指定的小节优先；继续阅读使用已存小节；小节失效时使用保存的比例；首次阅读从开头开始。
- 用户可手动标记已读或未读。到达底部不能自动视为掌握或完成学习。
- 阅读比例表示浏览位置；分类完成度只计算用户手动标记已读的正文章节，目录页不进入分母。
- 清除浏览器数据、更换浏览器或更换站点域名后，本地记录不会自动迁移；设置页说明这一点并提供导出入口。
- 验收：刷新或关闭后重新打开，同一浏览器可恢复最近章节及阅读小节；明确锚点跳转不被旧记录覆盖。

### F06 — 书签（P0）

- 收藏整篇章节或某个小节；再次收藏同一目标不重复创建。
- 我的阅读页面按收藏时间显示书签，支持访问和移除。
- 收藏状态刷新后保持；内容更新导致目标失效时显示目标不可用，保留记录供用户移除。
- 验收：加入、重复加入、刷新、跳转、移除的行为与显示一致。

### F07 — 阅读设置（P0）

- 支持跟随系统、浅色、深色三种主题；正文提供 16、18、20 像素三档字号，默认 18 像素。
- 正文行高约 1.7～1.9，桌面阅读宽度约 720～860 像素；使用系统字体，避免下载大体积中文字体。
- 设置保存在当前浏览器；主题切换同时覆盖代码、表格、搜索面板和图片查看器。
- 验收：三种主题和各档字号下正文与操作按钮均可读、可用。

### F08 — 个人数据备份与恢复（P0）

- 一次导出进度、已读状态、书签和设置，JSON 中包含数据格式版本和导出时间。
- 导入前检查格式、版本与字段，展示待导入数量，再由用户执行合并；错误文件不能改变现有数据。
- 同一记录以较新的更新时间为准，未知章节保留但标记暂不可用；不重复创建书签。
- 清除记录操作需确认；清除范围仅包含本项目的个人数据。
- 浏览器存储不可用时，阅读和搜索继续可用，显示“本次记录无法保存”的明确状态。
- 验收：导出后清除，再导入，能够恢复相同书签、已读状态、进度和设置。

### F09 — 来源与内容版本（P0）

- 每篇阅读页提供明显的作者/项目署名及原文链接；原文链接指向实际导入的源提交。
- 保留原文参考资料；关于页保存上游 README 的许可说明与许可链接。
- 上游 README 包含 CC BY-NC-SA 4.0 链接，导入时保留原声明及第三方资料来源；阅读站代码与导入内容分别说明许可。
- 区分内容快照、导入时间、站点发布时间。只有取得准确的文件历史后才能展示“正文最后修改时间”，不能用部署时间替代。
- 验收：任一正文页可追溯至对应源文件；站点没有把原文作者替换为站点开发者。

### F10 — 静态发布与访问（P0）

- 提供可复现的本地构建、预览、内容校验和发布说明。
- 浏览器阅读期间不依赖 GitHub API 或原站点在线；页面、索引及核心插图由本站提供。
- 在配置的部署子路径下，首页、深层阅读页、刷新、图片、搜索和 404 均能正常使用。
- 阿里云部署必须验证服务器内访问与用户网络的实际访问，不能只凭 Nginx 监听或本机 HTTP 200 宣布公网可用。
- 验收：电脑及手机浏览器打开实际地址，完成搜索、阅读、继续阅读和书签操作。

## 6. 内容导入与更新规则

导入流程为：固定上游提交 → 枚举源文件 → 内容清单与别名映射 → 清洗与转换 → 图片整理 → 链接校验 → 搜索索引与网页构建 → 发布。

1. **固定版本。** 初次以已检查的提交作为可复现输入；后续更新显式选择提交，记录完整 SHA，不在每次普通构建时隐式拉取最新内容。
2. **完整分类。** 175 个源 Markdown 文件都要在导入报告中归入正文、目录、跳转、重复或排除项。每个排除项记录理由，避免静默漏掉独立内容。
3. **去重与别名。** 例如 `算法.md`、`Leetcode 题解.md` 在该快照中是跳转入口，应映射到有效目录；`设计模式 - 目录1.md` 属于重复目录候选。`SQL.md` 等文件只有在确认与其他文件重复后才能排除。
4. **路径与锚点。** 处理大小写、空格、双空格、中文及百分号编码；维护源路径到稳定路由的映射。路径调整使用别名表，标题修改不使书签和进度失效。
5. **安全转换。** 保留必要的安全 HTML 排版标签，剔除脚本、事件处理属性、危险协议及主动执行内容。导入的笔记不得成为可执行组件、MDX 或脚本来源。
6. **插图本地化。** 优先匹配源仓库 `notes/pics/` 中对应文件；缺失时在构建阶段获取允许来源的图片并保存到本站。建立图片来源到本地资源的映射，去重且保留来源，不在阅读时临时代理下载。
7. **失败可见。** 缺失图片必须出现在报告中；正文提供替代说明和原图来源。关键示意图、公式图缺失时先修复再发布，非关键素材缺失必须明确列为已知问题。
8. **校验后更新。** 断开的站内页面链接、重复 ID、重复路由、未处理源文件导致校验失败；外部参考链接失效记入报告，不必阻塞全部正文阅读。
9. **保护个人记录。** 内容更新不得更换仍对应同一章节的 ID。删除章节时保留个人记录并提示不可用；进度与书签不随内容重新导入而重置。

每次导入报告至少包含：上游提交、有效正文与目录数量、排除和重复项、别名映射、新增/变更/删除章节、图片处理结果、断链结果。

## 7. 数据与状态约定

内容清单随构建产物发布，个人数据仅存在浏览器。两类数据分开管理。

| 数据 | 关键字段 |
| --- | --- |
| 内容清单 | `noteId`、`title`、`categoryId`、`groupId`、`order`、`route`、`sourcePath`、`sourceUrl`、`sourceCommit`、`contentHash`、`pageType` |
| 阅读记录 | `noteId`、`anchor`、`scrollRatio`、`lastVisitedAt`、`completed`、`updatedAt` |
| 书签 | `noteId`、`anchor`、`createdAt`、`updatedAt`；按章节和锚点联合去重 |
| 阅读设置 | `theme`、`fontSize`、`updatedAt` |
| 导出文件 | `schemaVersion`、`exportedAt`、阅读记录、书签、设置 |

`noteId` 是独立稳定 ID，不包含内容哈希、上游提交或标题。`scrollRatio` 取值为 0～1。日期使用带时区的 ISO 8601 字符串，界面按用户本地时间显示。

本地存储使用项目专属键前缀并包含格式版本，推荐首版使用 `localStorage`。实现时兼容静态预渲染环境，仅在浏览器端读写；导入、读取失败应安全降级，不阻止正文显示。

## 8. 非功能要求

| 维度 | 要求与验证方式 |
| --- | --- |
| 响应式 | 至少验证 375、768、1440 像素宽度；目录、搜索、图表和设置无遮挡 |
| 浏览器 | 发布时记录实际测试的桌面 Chrome、macOS Safari、iOS Safari、Android Chrome 版本 |
| 可访问性 | 核心操作可用键盘完成，焦点可见；弹层管理焦点，按钮有名称；文本对比度按 WCAG AA 目标检查 |
| 首屏性能 | 发布地址在冷缓存移动模拟下抽测三页，目标 LCP ≤ 3 秒、CLS ≤ 0.1；记录测速环境和结果 |
| 搜索性能 | 索引准备完成后，典型查询在 500 毫秒内显示结果；首次索引下载展示加载状态 |
| 资源加载 | 正文静态生成；搜索按需加载；首屏以外图片延迟加载；不预加载全部章节 |
| 隐私 | 不上传进度、书签、设置或搜索词，不接入第三方统计；Nginx 普通访问日志与个人记录区分说明 |
| 安全 | 清洗上游 HTML、校验导入 JSON；站点源码与发布产物不包含私钥、令牌、密码或服务器敏感配置 |
| 可维护性 | 内容清单、转换规则、主题扩展和个人记录逻辑分离；依赖锁定版本 |
| 更新稳定性 | 同源站点更新后个人数据保留；旧链接通过别名兼容；缺失目标不导致页面崩溃 |

## 9. 已确定的技术方案

采用 **Astro + React + TypeScript**。Astro 管理 Markdown 内容并在构建阶段生成静态 HTML，React 实现搜索、书签、进度、我的阅读和设置；全文搜索采用 Pagefind 扩展版，在静态构建后生成索引。个人数据使用 localStorage，多个交互区域通过 Nano Stores 共享状态。[Astro React 集成](https://docs.astro.build/en/guides/integrations-guide/react/)、[Pagefind 静态搜索](https://pagefind.app/docs/)

开发基线为 Astro 7.3.8、React 19.3.0、TypeScript 5.9.3、Node.js 24 LTS，使用 npm 和锁文件管理依赖。TypeScript 版本按 Astro 类型检查工具的支持范围选择。完整模块职责、版本与初始化检查见配套的技术选型文档。中文分词和混合技术词必须用 F03 的查询集验证，不能仅安装搜索库就视为完成。

运行架构为：本地源内容与同步脚本 → 清单及校验 → 静态构建产物 → 阿里云 Nginx → 浏览器。首版无需运行 Node 服务、PM2、数据库、Redis 或搜索服务器；Docker 不作为必需部署方式。

### 10.3 发布、验证与回退

1. 构建并完成内容、断链和功能检查，生成发布清单及构建产物校验值。
2. 上传至新的版本目录，保留 Git 标准文件权限；不得覆盖旧版本正在使用的文件。
3. 首次配置或配置变更前备份相关 Nginx 文件。修改后运行配置检查，通过后再平滑加载，并确认宝塔不会覆盖设置。
4. 切换当前版本；普通内容更新尽量只切换静态产物。
5. 验证首页、至少三个深层页面、搜索索引、图片和 404；从用户电脑和手机实际访问。
6. 验证既有服务访问状态与发布前基线一致，记录版本、地址及结果。
7. 出现问题时将 `current` 切回上一版本；若配置变更是原因，恢复备份并检查后平滑加载。保留当前与上一版本，清理只针对本项目的过期发布目录。

HTML 使用短缓存或重新验证；带哈希资源可长缓存。资源发布方案需兼容发布前已经打开的页面，例如保留前一版本资源，避免新版本切换后旧页面请求资源出现 404。

部署说明需用中文解释所用命令的用途、关键参数、成功判断方式及回退方法。公网访问未通过时，应记录阻塞点，不把服务器内部成功等同于整体上线成功。
